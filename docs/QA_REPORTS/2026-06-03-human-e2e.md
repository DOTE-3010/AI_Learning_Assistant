## Blockers

- Fixed: `run_desktop.command` could appear blank/stuck during human double-click launch because it performed Docker checks before opening the Electron shell. The human could not proceed to product E2E from the clickable launcher.
- Fixed pending human retest: Model settings now prefill documented non-secret Qwen defaults, including China-site base URL `https://dashscope.aliyuncs.com/compatible-mode/v1`, model `qwen-plus`, provider `openai_compatible`, context window `1000000`, and streaming `true`; API key remains empty.
- Fixed pending human retest: Workbench run/status stages now appear under a localized stage-progress surface with current-stage text instead of an unexplained bare word strip.
- Fixed pending human retest: Preview tabs now switch visibly between Code, Source, Logs, and Manifest. Root cause was an overly broad `[data-intent]` click binding that treated clicks inside the preview shell as artifact-intent selection and reset `previewTab` to the primary code view.
- Fixed and API-retested: Live Qwen provider auth failed because the default endpoint targeted Singapore/international while the supplied real key belongs to the China site. Defaults and the existing local saved profile were switched to the China (Beijing) endpoint; `/api/settings/model-profiles/test` now succeeds with `qwen-plus`, and a minimal live `code_homework` run reaches `succeeded`.
- Fixed and API-retested: Live `essay_latex` generation failed because the Docker runtime installed `fonts-lmodern` but not the Debian `lmodern` package that provides `lmodern.sty`; after the dependency fix, the same source progressed to a model-produced table alignment error. The LaTeX pipelines now make one bounded model-assisted repair attempt after source-level compile failures, then recompile before failing as `compile_failed`.

## Risks

- Full human E2E is still incomplete. The human still needs to verify auth, settings, uploads, all four artifact modes, preview affordances, revision flow, and English/Simplified Chinese/Traditional Chinese layouts.
- Live Qwen/OpenAI-compatible provider and live web-search behavior remain external-configuration decisions from the prior agent integration report.
- Regional Qwen API keys may require a base URL different from the documented China (Beijing) default. The default should still be editable and provider errors should remain clear.
- Existing failed runs remain failed historical records. Users should rerun after this fix to create a new succeeded run rather than expecting old run metadata to be rewritten.
